# ADR 0003. 가입 전 이메일 인증을 6자리 코드로 하고, 인증 데이터는 Redis에 둔다

- 상태: 확정
- 날짜: 2026-11-18

## 배경
- 이후 구글·카카오 로그인을 붙이면서 같은 이메일의 기존 계정과 연결하려 한다.
- 자체 가입 이메일이 인증되지 않은 상태라면, 남의 이메일로 먼저 가입해 두었다가 진짜 주인이 소셜 로그인할 때 계정이 연결되어 탈취로 이어질 수 있다.

## 결정
1. **가입 전에 인증한다.** 인증을 마쳐야 받는 signupToken으로만 가입할 수 있고, 가입 이메일은 토큰에서 꺼낸다.
2. **6자리 코드**를 메일로 보낸다.
3. 코드·signupToken·요청 횟수는 **Redis에 TTL로** 저장한다.
4. 메일은 `EmailSender` 인터페이스로 분리해 **로컬은 Mailpit, 운영은 AWS SES**(둘 다 SMTP)를 쓴다.
5. **이미 가입된 이메일은 409로 알려준다.** 가입 여부 노출은 감수하고, IP별 요청 제한으로 대량 조회를 막는다.

## 선택지와 이유
| 결정 | 검토한 대안 | 고른 이유 |
|---|---|---|
| 가입 전 인증 | 가입 후 링크 인증 | users에는 인증된 회원만 있어 소셜 계정 연결 시 따로 확인할 게 없다. 미인증 계정 제한·정리 배치가 필요 없다 |
| 6자리 코드 | 인증 링크 | PC에서 가입하고 휴대폰으로 메일을 봐도 된다. 프런트에 별도 인증 페이지가 필요 없다 |
| Redis + TTL | DB 테이블 | 몇 분만 필요한 데이터라 만료 시 자동 삭제된다. 쿨다운(`SET NX`)과 횟수 제한(`INCR`)이 간단하다. 이후 캐시·순위에서도 Redis를 쓴다 |
| 409로 가입 여부 알림 | 항상 같은 202 + "이미 가입됨" 안내 메일 | 안내 메일 방식은 계정 열거를 막지만, 사용자가 메일함을 열어봐야 상황을 안다. 중고책 서비스 가입 여부는 민감도가 낮다고 보고 UX를 우선했다 |

## 보안 장치
- 코드: `SecureRandom` 생성, SHA-256 해시로 저장, 5분 유효, 5번 틀리면 폐기
- 코드 확인(조회 → 틀린 횟수 증가 → 비교 → 삭제)은 **Lua 스크립트 하나로** 실행해, 동시 요청이나 새 코드 발급이 끼어들어도 토큰이 두 번 발급되거나 새 코드가 지워지지 않는다.
- 요청 제한: 같은 이메일 60초 쿨다운·하루 10회, 같은 IP 1시간 20회. 카운터의 `INCR`과 첫 `EXPIRE`도 Lua로 묶어 TTL 없는 카운터가 남지 않게 한다.
- signupToken: 256비트 무작위 값, 10분 유효, 가입 성공 시에만 소모(닉네임 중복 등 실패 시 재시도 가능)
- 메일은 `@Async`로 보내 메일 서버 지연이 API 응답에 영향을 주지 않는다.

## 감수하는 점
- 가입 여부 노출(계정 열거). 열거한 목록을 이용한 비밀번호 대입은 로그인 시도 제한으로 대응한다.
- IP 제한은 프록시 뒤에 배포할 때 실제 클라이언트 IP를 받도록 설정해야 의미가 있다.
- 메일 발송 실패는 비동기라 사용자에게 바로 알리지 못한다. 로그로 남기고, 사용자는 재발송으로 다시 받는다.
